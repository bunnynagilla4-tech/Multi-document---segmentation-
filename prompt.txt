## 2. Project Idea

Online news about the same event is published by multiple news sources. These articles may repeat facts, use different wording, emphasize different details, or contain overlapping information.

Reading every article individually takes time and can make it difficult to identify the most important facts.

NewsLens should accept multiple news articles, identify related articles, group them into candidate news events, and generate a concise summary that combines useful information from the articles.

The system should help users understand:

* What happened?
* Who was involved?
* Where did the event occur?
* When did it occur?
* What are the most important facts?
* What information is repeated across articles?
* What additional details do different articles contribute?

The system must not invent facts or treat uncertain information as confirmed.

## 8. Article Similarity and Event Clustering

Implement a similarity pipeline using TF-IDF and cosine similarity as the initial baseline.

Requirements:

* Calculate article similarity.
* Find the most similar articles.
* Support a configurable similarity threshold.
* Cluster articles into candidate event groups.
* Display the titles and article counts for each group.
* Allow users to inspect articles within a group.
* Provide a way to review or adjust cluster assignments where feasible.
* Explain that semantically related articles can still describe different events.

For larger datasets, do not construct an enormous dense article-by-article similarity matrix by default. Use sparse matrices, nearest-neighbor retrieval, batching, or another scalable method.

Benchmark performance on representative dataset sizes.

If the baseline clustering separates articles that clearly describe the same event, diagnose and tune the approach rather than claiming perfect clustering.

## 9. Summarization Methods

### A. Extractive summarization

Create a method that selects important sentences from the input articles.

Requirements:

* Score sentence importance using a documented method.
* Reduce unnecessary repeated sentences.
* Preserve original wording.
* Return a configurable summary length.
* Track which article and sentence each selected sentence came from.
* Avoid duplicate sentences in the final result.

### B. Abstractive summarization

Use a compatible pretrained summarization model.

Requirements:

* Provide model-loading code with version-compatible dependencies.
* Handle model download failures and unsupported model configurations.
* Use reasonable input-length limits.
* Split long articles or article groups into chunks when required.
* Combine intermediate summaries carefully.
* Avoid claiming that generated details are factually verified.
* Display a useful message if the model cannot load.
* Include a smaller or extractive fallback for machines with limited resources.

Never assume a particular Hugging Face pipeline task or model works without testing it in the selected environment.

### C. Hybrid summarization

Combine extractive and abstractive approaches.

The hybrid approach should:

* Identify important information from multiple articles.
* Reduce repeated content.
* Generate a readable summary.
* Preserve traceability to source articles.
* Make it possible for a user to inspect supporting source passages.
* Avoid adding unsupported facts.

Do not simply concatenate multiple summaries and call the result hybrid. Implement and document a meaningful combination strategy.

### D. Summary comparison

Let users compare:

* Original article text
* Extractive summary
* Abstractive summary
* Hybrid summary

Show word counts and compression ratios where useful.
